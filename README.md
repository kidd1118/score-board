# NBA Score Board

NBA 資料儀表板，包含四個頁面：

- **Games**：今日即時比分（進行中的比賽每 30 秒自動更新），也可查詢任意日期的賽果；每場比賽有完整數據頁，並顯示 Fantasy 積分
- **Teams**：東西區戰績榜，以及各隊的本季數據排名、每場得失分差、近期賽果與球員名單
- **Players**：搜尋球員，查看基本資料、生涯平均與逐季數據
- **Daily Fantasy**：多人遊戲，每天在薪資上限內挑 6 位球員組成陣容，依當天實際數據計算積分，並有當日、每週、每月與總排行榜和成就徽章

前端是 React（Create React App），後端是 FastAPI，資料來自 [nba_api](https://github.com/swar/nba_api)。

## Games 頁的日期選擇

- **日期列**：頁面上方顯示所選日期前後共 7 天（手機上 5 天），點一下就切換到該天；`‹` `›` 前後移動一天，「今天」標示目前即時比分所在的日期
- **跳到任意日期**：右上角的日期欄位可以直接選日期，「今天」按鈕回到即時比分
- **網址會記住日期**：例如 `#/games/2026-11-20`，重新整理或分享連結都會停在同一天；`#/games` 則是今天
- **日期是美國當地日期**：NBA 以美國日期排賽程，所以在台灣看到的「今天」常常是台灣的前一天
- **開賽時間換算成你的時區**，並附上日期，例如美國 11/25 晚上的比賽會顯示「11/26 上午08:00」

## Games 頁的比賽卡片與單場比賽頁

- **Fantasy 積分最高**：已開賽的比賽卡片下方，列出兩隊各自 Fantasy 積分最高的球員（依 Daily Fantasy 的積分規則）。比賽進行中會標示「即時」，跟著比分每 30 秒更新
- **完整數據與積分**：點卡片上的「完整數據與積分 ›」打開單場比賽頁，網址例如 `#/game/2026-11-24/0022600052`
  - 兩隊每位上場球員的積分、上場時間、得分、籃板、助攻、抄截、火鍋、失誤、犯規、投籃／三分／罰球命中與出手、正負值
  - **★** 是各隊積分最高的球員；有底色的列是有玩家選的球員，並列出是誰選的（比賽開打後陣容就公開，所以不會洩漏）
  - 先發球員名字旁標示位置；沒上場的球員列在表格下方
  - 勾選「依積分排序」可以改用積分排序，預設是官方 box score 的順序（先發在前）
  - 比賽進行中每 30 秒自動更新；手機上表格可以左右滑動，球員名字固定在左邊
- 「當日球員積分榜」裡的比賽也可以點，直接開啟該場比賽頁

## Daily Fantasy

### 加入遊戲

- 第一次進入 Daily Fantasy 頁，輸入一個**暱稱**就能加入（最多 20 字，不分大小寫，不能和別人重複）
- 加入後瀏覽器會記住一把**金鑰**，它是編輯你陣容的唯一憑證。點「顯示金鑰」可以複製，在其他裝置選「用金鑰登入」貼上就能繼續用同一個暱稱
- 登出或清除瀏覽器資料後，沒有金鑰就無法再編輯這個暱稱的陣容，請先把金鑰存好
- **更改暱稱**：點玩家名稱旁的「更改暱稱」，輸入新暱稱後儲存（按 Esc 或「取消」放棄）。規則和加入時相同（最多 20 字、不能和別人重複）：
  - 所有陣容、排行榜成績和「我的紀錄」都會跟著新暱稱，金鑰不變，其他裝置不用重新登入
  - 只改大小寫或空白（例如 `amy` → `Amy`）也可以
  - 舊暱稱會被釋出，之後別人可以用它加入

### 組陣容

每位玩家從當天（美國日期）有比賽的球隊中，為下列 6 個位置各挑一位球員：

| 位置 | 可選球員 |
| --- | --- |
| PG 控球後衛、SG 得分後衛 | 位置含 G（後衛）的球員 |
| SF 小前鋒、PF 大前鋒 | 位置含 F（前鋒）的球員 |
| C 中鋒 | 位置含 C（中鋒）的球員 |
| 第六人 | 任何球員 |

位置依 NBA 官方登錄，例如 `G-F` 的球員可以打 PG、SG、SF、PF 和第六人。同一位球員只能選一次。

### 薪資上限

6 位球員的**真實薪水**加總不能超過 **$148,465,000**。例如：

| 球員 | 2026-27 薪水 |
| --- | --- |
| Stephen Curry | $62,587,158 |
| Nikola Jokić | $59,033,114 |
| Giannis Antetokounmpo | $58,456,566 |

這三位加起來就已超過上限，平均下來每人只有約 $24.7M 可用，所以得在球星和便宜的角色球員之間取捨。

#### 怎麼算還能花多少

- 「剩餘薪資」＝ 上限 − 陣容中所有球員的薪水，**已鎖定（比賽已開始）的球員也算在內**
- 選某個位置時，可用金額是「剩餘薪資 + 這個位置原本球員的薪水」，因為換人時原本的球員會被換下。例如陣容只有 Stephen Curry（PG，$62,587,158）和 Jaylen Brown（SG，$57,078,728），剩餘 $28,799,114：
  - 選空著的 SF：最多 **$28.80M**
  - 更換 PG 的 Curry：最多 $28,799,114 + $62,587,158 = **$91.39M**
- 超出可用金額的球員在名單上無法選取，並標示「超出薪資」；就算直接呼叫 API，後端也會拒絕並回傳 400，例如「薪資總額 $178,122,452 超過上限 $148,465,000」
- 記得替還空著的位置留錢：其他人至少要新秀底薪 $1,357,763

#### 選人小技巧

- 名單可以改成依**性價比**（每百萬薪水的平均積分）、薪資高→低或低→高排序
- 勾選「只顯示薪資內」可以把買不起的球員藏起來
- 薪水金額在名單、陣容卡片上以百萬為單位（例如 $62.59M），游標移上去會顯示完整金額

#### 細節

- 薪水在**選入時就記下**，之後薪資資料更新也不影響已選的球員
- 不在合約名單上的球員（多半是雙向合約、10 天短約）以新秀底薪 $1,357,763 計，名單上標示 `*`
- 查看別人的陣容時看得到對方已用的薪資總額，但還沒開賽的球員仍不公開
- 加入薪資上限之前存下的陣容若已超過上限，仍會保留，但只能做讓薪資變少的更動（換成更便宜的球員或移除）
- 上限金額定義在 `src/api/nba_fantasy.py` 的 `SALARY_CAP`，新秀底薪是 `UNLISTED_SALARY`；修改後重新啟動後端即可

#### 薪資資料

薪資資料取自 [Basketball-Reference 的合約頁](https://www.basketball-reference.com/contracts/players.html)，存成快照 `src/api/salaries.json`（目前為 2026-27 球季）。交易、簽約或換季後執行下面的指令更新，再重新啟動後端：

```bash
cd src/api
../../.venv/bin/python update_salaries.py
```

快照用的是合約頁上**本季**（第一欄）的薪水。比對 NBA 球員時會忽略重音與 Jr./II 等字尾（`Nikola Jokić` = `Nikola Jokic`）。被裁的球員在舊東家還有剩餘薪資，會出現兩筆，這時採用**目前球隊**的合約。名字寫法不同時（例如 `Ron Holland` 和 `Ronald Holland II`），如果同隊只有一位同姓球員，也會對上。

### 球員狀態（傷兵報告）

選球員時，名單和陣容卡片上會標示球員當天能不能上場，避免選到不會上場的球員（沒上場就是 0 分）。

| 標籤 | 顏色 | 意思 |
| --- | --- | --- |
| `Out` | 紅 | 確定缺陣 |
| `Out for season` | 紅 | 本季報銷 |
| `Doubtful` | 橘 | 不太可能上場（約 25%） |
| `Questionable` | 黃 | 不確定（約 50%） |
| `GTD` | 黃 | Game-time decision，賽前才決定 |
| `Probable` | 綠 | 很可能上場（約 75%） |

沒有標籤代表沒有出現在傷兵名單上，可以正常上場。標籤一定附上文字，不會只靠顏色區分。

#### 在哪裡看得到

- **選球員名單**：球員名字旁的標籤，下一行是傷因（例如 Right Knee Inflammation）；游標移到標籤上會顯示狀態、傷因和資料來源
- **我的陣容卡片**：已選的球員如果被列入傷兵名單，同樣會顯示標籤和傷因，方便在開賽前換人
- **名單最下方**：官方報告的更新時間（美東時間，例如「11/25 5:30 PM ET 更新」），以及是否有用 ESPN 補充
- 勾選「**隱藏 Out 球員**」可以把確定缺陣（Out、Out for season）的球員藏起來；Questionable 等不確定的球員仍會顯示

狀態只在**開賽前**顯示。開賽後球員就鎖定了，以實際數據為準，不再顯示標籤。別人陣容中還沒公開的球員也不會顯示狀態。

#### 怎麼用

- 選了 `Questionable` 或 `GTD` 的球員，開賽前記得回來確認；狀態變成 `Out` 就趁比賽還沒開始換人
- 選 `Out` 的球員不會被擋下（狀態偶爾會在賽前改變），但如果真的沒上場就是 0 分
- 選球員名單打開後不會自動更新，想看最新狀態請**重新整理頁面**；陣容卡片在有比賽進行中時每 30 秒更新一次

#### 資料來源

| 來源 | 涵蓋範圍 | 狀態 |
| --- | --- | --- |
| [NBA 官方傷兵報告](https://official.nba.com/nba-injury-report-2025-26-season/)（PDF） | 今天和部分明天的比賽，比賽日每 15 分鐘更新 | Out、Doubtful、Questionable、Probable |
| [ESPN 傷兵資訊](https://www.espn.com/nba/injuries) | 所有球隊的目前狀態 | Out、Out for season、day-to-day（顯示為 `GTD`） |

- 某支球隊**已列入**當天的官方報告時，只採用官方報告；官方報告沒列的球員就是可以上場
- 球隊還沒列入官方報告時（例如兩天後的比賽），改用 ESPN 的目前狀態。ESPN 描述的是「現在」，越後面的日期越不準
- 官方報告的球員姓名以「姓, 名」排列，比對時會忽略重音和 Jr./II 字尾，跟薪資資料用同一套規則

#### 更新頻率與失敗處理

- 後端把兩個來源各暫存 **10 分鐘**，加上官方報告本身每 15 分鐘才發布一次，狀態最多可能晚約 25 分鐘
- 任一個來源連不上或解析失敗時，其他功能照常運作，只是少了那個來源的狀態；失敗會記住 2 分鐘後再重試，避免拖慢每次請求
- 重新啟動後端可以立即清除暫存

#### API

`GET /fantasy/{date}/pool` 的每位球員、`GET /fantasy/{date}/lineup/{name}` 的每個位置都有 `injury` 欄位，沒有狀態時為 `null`：

```json
{
  "status": "QUESTIONABLE",
  "label": "Questionable",
  "reason": "Right Groin Tendinitis",
  "source": "NBA"
}
```

`status` 可能是 `OUT`、`OFS`（本季報銷）、`DOUBTFUL`、`QUESTIONABLE`、`GTD`、`PROBABLE`；`source` 是 `NBA` 或 `ESPN`。`pool` 另外回傳 `injuryReport`：

```json
{
  "official": { "published": "2026-11-24T22:15:00", "url": "https://ak-static.cms.nba.com/referee/injury/Injury-Report_2026-11-24_10_15PM.pdf" },
  "espn": true
}
```

`published` 是美東時間；`official` 為 `null` 表示取不到官方報告，`espn` 為 `false` 表示取不到 ESPN。

#### 維護

程式在 `src/api/nba_injuries.py`。官方報告的列表頁網址 `INDEX_URL` 帶有球季名稱，換季後若名單上的狀態全部消失，先用瀏覽器確認 NBA 官網的新網址再更新。PDF 版面改變導致解析不到球員時，檢查 `parse_report()` 的正規表示式。

### 積分規則

每位球員的積分依當天的比賽數據計算，陣容總積分是 6 人的加總。

| 數據 | 每次 | 說明 |
| --- | --- | --- |
| 兩分球命中 | +2 | |
| 三分球命中 | +3 | |
| 罰球命中 | +1 | |
| 籃板 | +3 | 進攻和防守籃板都算 |
| 助攻 | +4 | |
| 抄截 | +5 | |
| 火鍋 | +5 | |
| 失誤 | −2 | |
| 犯規 | −2 | 個人犯規 |
| 未命中 | −1 | 投籃（含三分）和罰球沒進，每次都扣 |

#### 怎麼看這套規則

- **投進的球照實際分數計分**：兩分 2、三分 3、罰球 1，加起來就是球員當場的實際得分
- **每次沒投進扣 1 分**：投 10 中 4 的球員，雖然拿到分數，也會被扣 6 分。命中率高的球員比單純出手多的球員吃香
- **犯規和失誤都扣 2 分**：犯規麻煩多的長人，扣分會很明顯
- **最低 0 分**：每位球員單場最低 0 分，不會出現負分。扣分再多也只會讓那個位置記 0 分，不會拉低陣容裡其他球員的分數
- **沒有上場**的球員記 0 分

#### 計算範例

| 數據 | 次數 | 積分 |
| --- | --- | --- |
| 兩分球命中 | 2 | +4 |
| 三分球命中 | 3 | +9 |
| 罰球命中 | 2 | +2 |
| 籃板 | 2 | +6 |
| 助攻 | 4 | +16 |
| 抄截 | 1 | +5 |
| 火鍋 | 1 | +5 |
| 失誤 | 1 | −2 |
| 犯規 | 5 | −10 |
| 未命中 | 3 | −3 |
| **合計** | | **32 分** |

這位球員實際得 15 分（2×2 + 3×3 + 2）。

**低於 0 分的例子**：投籃 0 中 8、罰球 0 中 2、1 籃板、3 失誤、4 犯規：3 − 6 − 8 − 10 = −21，記為 **0 分**。

#### 在哪裡看得到

- **規則列**：頁面上方列出全部 10 項規則
- **陣容卡片**：右上角是這位球員目前的積分。下方數據列依序是得分、三分、籃板、助攻、抄截、火鍋、失誤、犯規、未中，例如 `15分 3三分 2板 4助 1抄 1鍋 1失誤 5犯規 3未中`
- **選球員名單**：「平均積分」用同一套規則，以球員**本季場均數據**計算（最低一樣是 0）；名單預設依這個數字排序，性價比排序也用它

#### 規則改變時

已結算的日子會記錄當時用的規則版本。規則改變後，舊版本算出的積分會在下次讀取時，依新規則重新計算；當日排行榜、總排行榜和「我的紀錄」也會跟著更新。

#### 資料來源與 API

- **比賽中與賽後**：NBA 即時 box score 的投籃、三分、罰球命中與出手數，以及籃板、助攻、抄截、火鍋、失誤、犯規
- **本季平均**：NBA stats 的球員場均數據（`LeagueDashPlayerStats`），後端暫存 6 小時

`GET /fantasy/{date}/lineup/{name}` 每個位置的 `stats` 和 `GET /fantasy/{date}/pool` 每位球員的 `avg` 使用同一組欄位，`points`、`avgPoints` 是算好的積分：

```json
{
  "played": true,
  "pts": 15, "fg2m": 2, "fg3m": 3, "ftm": 2, "miss": 3,
  "reb": 2, "ast": 4, "stl": 1, "blk": 1, "tov": 1, "pf": 5
}
```

`pts` 是實際得分，只用來顯示；積分由 `fg2m`、`fg3m`、`ftm` 計算。`played` 只出現在 `stats`。陣容回傳的 `scoring` 是目前的權重，例如 `{"fg2m": 2, "fg3m": 3, ..., "miss": -1}`。

#### 修改規則

1. 改 `src/api/nba_fantasy.py` 的 `SCORING`。新增的數據要同時加到 `scoring_stats()`
2. 把同一個檔案的 `SCORING_VERSION` 加 1，已結算的日子才會重新計算
3. 改 `src/FantasyDashboard.js` 的 `RULES`（規則列）；有新欄位時也加到 `STAT_LABELS`（數據列）
4. 更新這一節

### 玩法

- 點位置上的「選擇球員」，從名單挑人；名單預設依**本季平均積分**排序，可以用姓名或球隊縮寫（例如 `BOS`）搜尋，並標示 Out、Questionable 等球員狀態
- **比賽開始就鎖定**：球員的比賽一開打，就不能再被選入，已在陣容裡的也不能換下或移除；還沒開打的位置仍可以更換
- 比賽進行中，積分每 30 秒自動更新；沒有上場的球員記 0 分
- 陣容裡所有球員的比賽都結束後，當天積分會**結算**，並記錄在「我的紀錄」（含當天名次），點一下可以回到那一天
- 日期列和網址的用法與 Games 頁相同，例如 `#/fantasy/2026-11-20`；`#/fantasy` 是今天

### 一鍵最佳陣容

陣容上方的「⚡ 一鍵最佳陣容」會自動排好整個陣容：

- 依球員的**本季平均積分**，在**薪資上限內**挑出 6 人總分最高的組合（會算出真正的最佳解，不是從高分往下挑）
- **已開賽的球員不變**，只重排還沒鎖定的位置；陣容裡原本還沒開賽的球員會被換掉，所以會先跳出確認
- 被列為 **Out** 的球員不列入；Questionable 等狀態仍可能被選上，排好後請看下面的開賽前提醒
- 排好後會顯示預估積分（依本季平均），之後仍然可以手動更換任何位置

### 開賽前提醒

看自己還沒結算的陣容時，陣容上方會列出：

- **傷兵**：陣容裡還沒開賽的球員被列為 Out、Doubtful、Questionable 等狀態時，提醒你確認或換人
- **空位**：當天還有比賽沒開打，但陣容還有位置沒選時，提醒你沒選的位置記 0 分
- **下一位鎖定**：最快開賽的球員還有多久鎖定，每分鐘更新

### 球員近況

選球員名單裡，每位球員除了本季平均，還會顯示：

- **近 5 場**：所選日期之前最近 5 場比賽的平均積分，旁邊的小長條圖是這 5 場的積分（左舊右新），游標移上去會列出每場分數
- **▲ 手感火燙／▼ 手感低迷**：近 5 場平均比本季平均高或低 15% 以上
- 排序可以選「依近 5 場積分」
- 資料來自 NBA stats 的 `PlayerGameLogs`（本季所有例行賽逐場數據），後端暫存 1 小時；取得失敗時名單照常顯示，只是沒有近況

### 排行榜

- **當日排行榜**：所選日期所有玩家的積分與名次，比賽進行中會跟著更新。同分同名次
- **總排行榜**：累計所有**已結算**日子的總積分並排名，另外列出參加天數、平均、單日最佳與單日冠軍次數（當天至少兩人參加，且所有人都結算後才算）
- **本週／本月**：總排行榜右上角可以切換成只算所選日期那一週（週一到週日）或那個月，比較晚加入的玩家也有機會拿第一。標題下方會列出計算的日期範圍
- 點排行榜上的玩家可以查看該玩家當天的陣容。**別人還沒開賽的球員不會公開**，只顯示「已選擇，開賽後公開」，避免照抄；自己的陣容一律看得到

### 成就徽章

總排行榜的玩家名字旁會顯示拿到的徽章，游標移上去會說明。徽章一律依**所有日子**計算，切換本週／本月不影響：

| 徽章 | 名稱 | 條件 |
| --- | --- | --- |
| 👑 | 單日冠軍 | 拿過單日第一（當天至少兩人參加，且所有人都結算） |
| 💯 | 300 分俱樂部 | 單日總積分達到 300 分 |
| 🎯 | 神準 | 陣容裡有球員單場拿到 70 分以上 |
| 🔥 | 連續 7 天 | 連續 7 個比賽日都有組陣容（以有人組陣容的日子為準） |
| 📅 | 老玩家 | 參加滿 10 天 |

門檻在 `src/api/nba_fantasy.py` 的 `BADGES`、`CLUB_TOTAL`、`SNIPER_POINTS`、`STREAK_DAYS`、`VETERAN_DAYS`。

### 當日球員積分榜

列出所選日期**所有出賽球員**的積分前 10 名，不限有沒有被選入陣容，可以看看當天誰最值得選、自己錯過了誰。位置在「當日排行榜」下方、「總排行榜」上方。

#### 表格欄位

| 欄位 | 內容 |
|---|---|
| 名次 | 依積分排名，同分同名次（例如兩人並列第 2，下一位是第 4） |
| 球員 | 姓名、球隊、對手與比賽狀態（比分或「第 3 節」等），下方是數據列，格式和陣容卡片相同 |
| 被選 | 有幾位玩家選了這位球員；游標移到數字上會列出玩家暱稱，沒人選顯示 `–` |
| 積分 | 依「積分規則」計算，最低 0 分 |

你陣容裡的球員整列會標示，並加上「你的球員」。

#### 排名方式

- 只計算**已開賽**的比賽（進行中或已結束），有上場的球員才會列入；沒上場的不列
- 依積分由高到低，同分時依姓名排序，並給相同名次
- 第 10 名同分時全部列出，所以可能超過 10 人
- 只有已開賽的球員才會上榜，所以「被選」不會洩漏別人還沒公開的陣容

#### 什麼時候會更新

- 比賽進行中每 30 秒自動更新；當天比賽都結束後就不再自動更新
- 表格下方會註明還有幾場沒開賽
- 換日期時會重新載入；沒有比賽的日子顯示「這天沒有比賽」，比賽都還沒開打時顯示「比賽開始後才會有球員積分」

#### 資料來源與 API

使用和陣容積分相同的 box score：先讀 NBA 即時 CDN，失敗時改用 NBA stats 的 `BoxScoreTraditionalV3`；比賽進行中暫存 30 秒，已結束的比賽暫存 6 小時。每場比賽只抓一次，所有玩家共用。

`GET /fantasy/{date}/top` 回傳（2026-11-24 的第 1 名）：

```json
{
  "date": "2026-11-24",
  "games": 3,
  "started": 3,
  "live": false,
  "players": [
    {
      "id": 1641709,
      "name": "Ausar Thompson",
      "team": "DET",
      "position": "PF",
      "game": { "id": "0022600052", "status": 3, "statusText": "Final", "startTimeUTC": null, "home": false, "opponent": "ORL" },
      "stats": { "played": true, "pts": 6, "fg2m": 3, "fg3m": 0, "ftm": 0, "miss": 0, "reb": 10, "ast": 7, "stl": 1, "blk": 4, "tov": 2, "pf": 1 },
      "points": 83,
      "pickedBy": [],
      "rank": 1
    }
  ]
}
```

- `game`：這位球員的比賽，`opponent` 是對手、`home` 表示是否主場；`games`：當天比賽數；`started`：已開賽的場數；`live`：是否有比賽正在進行（前端用來決定要不要自動更新）
- `stats` 欄位和陣容的 `stats` 相同（見「積分規則」的「資料來源與 API」）
- `pickedBy`：選了這位球員的玩家暱稱，依名稱排序

#### 修改

- 改顯示人數：`src/api/nba_fantasy.py` 的 `TOP_PLAYERS`，並同步改 `src/FantasyDashboard.js` 標題的「前 10 名」
- 改更新頻率：`src/FantasyDashboard.js` 的 `REFRESH_MS`（和陣容、當日排行榜共用）

### 資料儲存

所有玩家與陣容存在 SQLite 資料庫 `src/api/data/fantasy.db`（`src/api/data/` 已加入 `.gitignore`），程式在 `src/api/store.py`。

| 資料表 | 內容 |
| --- | --- |
| `users` | `key`（小寫的暱稱）、`name`（顯示的暱稱）、`token`（金鑰） |
| `lineups` | `date`、`user_key`、`slots`（6 個位置的球員，JSON）、`final_total`（結算積分）、`scoring_version`、`pick_points`（結算時每位球員的積分，JSON，給成就徽章用）、`updated_at` |

- **同時寫入很安全**：每次寫入（加入、改暱稱、存陣容、結算）都在一個交易裡完成，多位玩家同時操作，或開發模式和固定網址模式兩個後端同時跑，都不會互相覆蓋
- **從舊版升級**：第一次啟動時，如果有舊的 `fantasy.json`，會自動匯入資料庫，原檔改名為 `fantasy.json.imported` 留作備份
- **自動備份**：後端每天把資料庫備份到 `src/api/data/backups/fantasy-<時間>.db`，保留最新 14 份
- **手動備份或匯出**（後端開著也可以）：

  ```bash
  cd src/api
  ../../.venv/bin/python backup_fantasy.py                    # 備份到 data/backups/
  ../../.venv/bin/python backup_fantasy.py --json export.json # 匯出成好讀的 JSON
  ```

- **還原**：停掉後端，把備份檔複製成 `src/api/data/fantasy.db`（並刪掉同目錄的 `fantasy.db-wal`、`fantasy.db-shm`），再啟動
- **直接查詢**：例如 `sqlite3 src/api/data/fantasy.db "SELECT date, user_key, final_total FROM lineups ORDER BY date"`
- 要換位置可以設定環境變數 `FANTASY_DB_FILE`（資料庫）、`FANTASY_BACKUP_DIR`（備份資料夾）、`FANTASY_DATA_FILE`（要匯入的舊 JSON）
- 改成多人版之前存下的陣容會歸到暱稱「玩家1」，第一個用「玩家1」加入的人會接手這些紀錄

> 金鑰只用來防止別人改你的陣容，不是正式的帳號系統；部署到公開網路前請加上 HTTPS。

## 啟動

前後端要各開一個終端機同時執行。

### 1. 後端（FastAPI，port 8000）

第一次執行先建立虛擬環境並安裝套件：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

啟動：

```bash
cd src/api
../../.venv/bin/uvicorn main:app --reload --port 8000
```

啟動後可以打開 <http://localhost:8000/docs> 查看與測試所有 API。

> 用 VS Code 的話，先把 Python 直譯器選成 `.venv/bin/python`，再用「Run and Debug」裡的 **Python Debugger: FastAPI** 啟動，效果相同。

### 2. 前端（React，port 3000）

第一次執行先安裝套件：

```bash
npm install
```

啟動：

```bash
npm start
```

打開 <http://localhost:3000>。前端對 API 的請求會透過 `package.json` 裡的 `proxy` 轉到 `http://localhost:8000`，所以**後端必須先啟動**，否則頁面會顯示無法取得資料。

## 固定網址（Tailscale Funnel）

讓其他人從網路上連進來，網址固定為 `https://<電腦名稱>.<tailnet 名稱>.ts.net`。網址綁的是這台電腦在 Tailscale 裡的名稱，跟 IP 無關，所以換網路、IP 變了都照樣連得上。不用設定路由器，HTTPS 憑證也會自動處理。

這個模式由後端同時提供網頁和 API，整個網站只用一個 port（預設 **8080**），不會和開發用的 8000、3000 衝突。

### 第一次設定

1. 安裝並登入 Tailscale（需要一個 Tailscale 帳號，個人使用免費）：

   ```bash
   brew install tailscale
   sudo brew services start tailscale   # 背景執行，開機自動啟動
   tailscale up                          # 會給一個網址，用瀏覽器登入
   ```

   也可以從 <https://tailscale.com/download> 安裝 Mac App，`scripts/serve.sh` 兩種都找得到。

2. （選擇性）把電腦名稱改成好記的名字，網址會跟著變，例如 `https://nba.<tailnet 名稱>.ts.net`：

   ```bash
   tailscale set --hostname=nba
   ```

3. 第一次開啟 Funnel 時，終端機會出現一個連結，要你在 Tailscale 管理頁面同意開啟 **HTTPS** 和 **Funnel**。打開連結按同意後，再執行一次下面的啟動指令

### 啟動

```bash
scripts/serve.sh
```

會依序：建置前端（`npm run build`）→ 開啟 Funnel → 在 8080 啟動後端。最後印出的 `tailscale funnel status` 就是公開網址。

- 前端沒有改過時，可以用 `scripts/serve.sh --no-build` 省掉建置
- 換 port：`PORT=9000 scripts/serve.sh`
- 第一次開啟後，DNS 可能要幾分鐘才生效
- 沒有安裝 Tailscale 時，腳本只會在本機啟動（<http://localhost:8080>）

### 要注意的事

- **電腦要開著**：網站跑在這台 Mac 上。睡眠、關機或停掉 `serve.sh`，網站就連不上；網址不會變，重新執行 `scripts/serve.sh` 就恢復
- **Funnel 會一直開著**：停掉 `serve.sh` 後 Funnel 設定仍然保留（重開機也是），只是連進來會看到錯誤頁。要完全關閉公開網址：`tailscale funnel reset`
- **任何人都能進來**：知道網址的人都能加入遊戲。金鑰經由 HTTPS 傳送，但仍不是正式的帳號系統
- **NBA 請求量不會隨人數增加**：後端會在背景預先抓取 NBA 資料（見「NBA 資料預先抓取」），訪客只讀後端記憶體裡的資料
- **改了程式要重新啟動**：公開網址提供的是 `build/` 裡的檔案，改了前端要重新執行 `scripts/serve.sh`（不加 `--no-build`）；這個模式的後端也不會自動重新載入
- **資料是同一份**：開發模式和這個模式都讀寫 `src/api/data/fantasy.db`，兩邊同時開著也不會互相覆蓋

## NBA 資料預先抓取

後端啟動後會有一個背景工作，定時向 NBA 更新今天的資料，網頁要資料時直接讀後端記憶體裡的版本：

| 資料 | 更新頻率 |
| --- | --- |
| 今天的比賽與比分 | 有比賽進行中每 15 秒，沒有時每 60 秒 |
| 進行中比賽的 box score | 每 15 秒，一場一場依序抓（間隔 1 秒） |
| 已結束比賽的 box score | 抓一次，保留 6 小時 |
| 球員名單與本季平均 | 每 6 小時 |
| 近 5 場（逐場數據） | 每 1 小時 |
| 傷兵報告 | 當天還有比賽沒開打時，每 10 分鐘 |

- **為什麼**：以前是有人開網頁、暫存又剛好過期時才去抓，人越多、分頁越多，請求越多，球員積分榜還會一次同時抓好幾場 box score，容易被 NBA 封鎖。現在 NBA 的請求量固定，跟有多少人在看無關
- **訪客幾乎不會自己去問 NBA**：背景工作執行時，網頁用的暫存時間拉長到 90 秒。背景工作卡住時，過了 90 秒訪客的請求還是會自己去抓，不會一直看到舊資料
- **失敗時**：沿用上一次成功的資料，下一輪再試（同一份資料失敗後 60 秒內不重試）
- **只抓今天**：其他日期仍是有人看時才抓，已結束的日期保留 6 小時
- **查看狀態**：`GET /status` 回傳最近一輪的時間、錯誤、進行中的比賽數等
- **關閉**：啟動後端前設定環境變數 `NBA_PREFETCH=0`
- 開發模式（8000）和固定網址模式（8080）同時開著時，兩個後端各自抓一份，NBA 請求量是兩倍；只需要一個時，把另一個停掉或設 `NBA_PREFETCH=0`
- 每天的資料庫自動備份也是這個背景工作做的
- 程式在 `src/api/prefetch.py`

## API

| 路徑 | 說明 |
| --- | --- |
| `GET /status` | 背景預先抓取的狀態 |
| `GET /games/` | 今日比賽（即時比分） |
| `GET /games/?date=YYYY-MM-DD` | 指定日期（美國日期）的比賽；格式錯誤回傳 400 |
| `GET /team/standings` | 本季東西區戰績 |
| `GET /team/{team_id}/profile` | 球隊資料、數據排名、賽果與球員名單 |
| `GET /team/{abbr}` | 以縮寫查詢球隊，例如 `BOS` |
| `GET /player/?active=true` | 球員名單（`active` 省略則包含退役球員） |
| `GET /player/{player_id}/profile` | 球員資料與逐季數據 |
| `GET /player/{name}` | 以全名搜尋球員 |
| `POST /fantasy/users` | 以 `{"name": "暱稱"}` 加入遊戲，回傳 `{name, token}`；暱稱已被使用回傳 409 |
| `GET /fantasy/me` | 以 `X-Fantasy-Token` 標頭查詢自己的暱稱；金鑰無效回傳 401 |
| `PATCH /fantasy/me` | 更改自己的暱稱（需 `X-Fantasy-Token`），body 為 `{"name": "新暱稱"}`；暱稱已被使用回傳 409、格式不符回傳 400 |
| `GET /fantasy/{date}/lineup/{name}` | 指定玩家當天的陣容與積分；不是本人（沒帶正確金鑰）時，未開賽的球員會隱藏 |
| `PUT /fantasy/{date}/lineup` | 儲存自己的陣容（需 `X-Fantasy-Token`），body 為 `{"slots": {"PG": 球員ID, ..., "6TH": null}}`；違反規則（含超過薪資上限）回傳 400 |
| `GET /fantasy/{date}/pool` | 當天可選的球員名單（含可打的位置、本季平均、近 5 場 `recent`、薪水與傷兵狀態 `injury`；`injuryReport` 為官方報告的更新時間） |
| `POST /fantasy/{date}/lineup/auto` | 一鍵最佳陣容（需 `X-Fantasy-Token`）：依本季平均在薪資上限內排出最佳組合並儲存，回傳陣容與預估積分 `projected` |
| `GET /fantasy/{date}/leaderboard` | 當日排行榜 |
| `GET /fantasy/{date}/top` | 當日所有出賽球員的積分前 10 名（含數據、對手與 `pickedBy` 選了該球員的玩家） |
| `GET /fantasy/leaderboard` | 總排行榜（只計已結算的日子），每位玩家含 `badges`；加上 `?period=week&date=YYYY-MM-DD` 或 `period=month` 只算那一週／那個月 |
| `GET /fantasy/{date}/game-leaders` | 當天每場已開賽比賽中，兩隊各自 Fantasy 積分最高的球員 |
| `GET /games/{date}/{game_id}` | 單場比賽的完整數據，每位球員含積分與 `pickedBy`；找不到比賽回傳 404 |
| `GET /fantasy/salary` | 薪資上限、薪資資料的球季與未列名球員的薪資 |
| `GET /fantasy/history/{name}` | 指定玩家所有有陣容的日期、積分與名次 |

## 常見問題

- **後端啟動時出現 `ModuleNotFoundError: No module named 'pypdf'`**：拉了新版程式碼後要重新安裝套件：`.venv/bin/pip install -r requirements.txt`（解析官方傷兵報告 PDF 需要 pypdf）。
- **出現「NBA 伺服器拒絕連線或沒有回傳資料」（舊版是 `Expecting value: line 1 column 1 (char 0)`）**：NBA 的伺服器暫時封鎖了這台電腦的 IP，通常是短時間內請求太多（例如很多分頁同時開著、比賽中一直自動更新）。封鎖會自己解除，等一段時間即可。這段期間：
  - 即時比分和 box score（`cdn.nba.com`）取不到時，後端會改用 NBA stats API（`stats.nba.com`），比分約 1 分鐘更新一次，比賽的領先球員不會顯示
  - 失敗後 60 秒內不會再向同一個來源請求；之前取得的資料會繼續顯示
  - 兩個來源都被封鎖時才會出現這個錯誤。少開幾個分頁可以讓封鎖早點解除
- **頁面顯示「連不上後端伺服器」（舊版是 `Unexpected token 'P', "Proxy erro"... is not valid JSON`）、終端機出現 `Proxy error ... ECONNREFUSED`**：後端沒有啟動或已經停止。開發模式照上面步驟啟動後端；用固定網址時重新執行 `scripts/serve.sh --no-build`。啟動後重新整理頁面。
- **後端回傳 502 `NBA API request failed`**：NBA 官方網站連線失敗或逾時（後端已自動重試一次）。NBA 會封鎖部分網路（例如雲端主機、某些 VPN），請換個網路再試。
- **比賽資料沒有馬上更新**：今天的比分由背景工作每 15 秒（沒有比賽進行時 60 秒）更新一次，網頁每 30 秒重新讀取，所以最多可能晚約 45 秒。其他日期：還有比賽沒打完的暫存 60 秒、全部打完的 6 小時。重新啟動後端即可清除。用 `GET /status` 可以看背景工作是否正常
- **資料庫被鎖定（`database is locked`）**：有其他程式長時間開著資料庫（例如 `sqlite3` 命令列正在交易中）。關掉那個程式即可；後端會等最多 30 秒再放棄
- **選「今天」看到的日期比台灣早一天**：這是正常的，日期依美國當地日期計算，台灣上午到下午之間通常會差一天。
- **球員大頭照或球隊 logo 沒顯示**：圖片直接從 NBA 的 CDN 載入，被封鎖時會自動隱藏，不影響其他資料。
- **Daily Fantasy 某位球員點不下去**：名單右側會寫原因——「已開賽」（比賽開始後鎖定）、「已在陣容」或「超出薪資」（可用金額不夠，先換掉一位高薪球員）。
- **球員薪水不對或顯示 `*`**：薪資快照可能過期（交易、新簽約），執行 `update_salaries.py` 更新後重新啟動後端。仍然是 `*` 代表合約頁上沒有這位球員，通常是雙向合約。
- **球員狀態沒有顯示，或名單下方寫「目前無法取得傷兵狀態」**：NBA 官方網站和 ESPN 都連不上（可能被網路封鎖）。2 分鐘後會自動重試；狀態只在還沒開賽的日期顯示。
- **官方報告的狀態和新聞不一樣**：官方報告每 15 分鐘才更新一次，後端又會暫存 10 分鐘，最多可能晚約 25 分鐘。
- **`update_salaries.py` 失敗**：Basketball-Reference 有流量限制，短時間內請求太多次會暫時被擋，等一陣子再試；出現 `no salaries found` 則是網頁格式改了，需要調整腳本。
